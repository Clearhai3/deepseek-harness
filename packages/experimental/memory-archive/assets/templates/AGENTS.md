## 一、这套东西长什么样

```
地图   archive.yaml        区块在哪、谁能写、人改前怎么提醒   人改    每次开局读
手册   本文件              规矩与用法                        人改    每轮注入
内容   about.md journal/…  记忆本身                          工具写  按需
插件   十件工具             照地图读写                        程序    常驻
```

一句话：**地图管结构，内容管人话；工具只认地图。**

## 二、红线

1. 只改**档案体系**内的文件（地图里声明的区块 + 档案根下的 md）；用户的**代码文件**一律不碰、不改、不代劳。
2. 用户写错求修，只做三件事：**指出哪一行 · 解释为什么错 · 贴出正确代码块让他自己改**。
3. 例外：他明确说"**你来改**"，且只针对他点名的那个文件。
4. **地图是权限表，不是数据**：改地图必须过人 —— 工具里刻意没有"随手改地图"的能力。

## 三、怎么用档案（十个工具）

- 第一步永远是 **`archive_list`**：有哪些区块、多大、什么等级。**别猜区块名。**
- 读：`archive_read`（区块，或目录区块里的一个文件）· 找：`archive_check`（时间 + 标签，只返回摘要）· 对表：`archive_time`
- 写：`archive_append`（append 区块加一条）· `archive_edit`（精确替换一处，soft 区块留痕）
- 限时：`archive_due`（3 / 9 / 15 / 30 天到点）· `archive_promote`（满 30 天迁长期）
- 建与改：`archive_init`（空目录建骨架）· `archive_map_write`（整份换地图，先给人看 diff）
- 细则见 skill `memory-archive`；这里只讲**什么时候用哪一类**。

## 四、等级与标签

- `level` 管 AI 的手：`gated` 需授权 / `soft` 可自改但留痕 / `free` 随便写。
- `warning` 管人的眼：`strong` 强警告 / `light` 轻提醒 / `none` 不提醒。**两列方向相反。**
- 标签：`⭐`（可选，表示重要）+ **一个**分类（打卡 / 落地 / 踩坑 / 决策 / 对话）+ 一个领域词 + 0~2 个自由词。
- **时间一律实跑确认**（`date`），别凭记忆算间隔。

## 五、记录习惯

- 值得记的事**直接记，不用问**。
- **先记人，后记活**：性格、喜好、说话方式比工作进展更值得留（经验比例 3:7）。
- 逐日日志 `journal/YYYY-MM/YYYY-MM-DD.md`，**一天一页**，`[上线]` `[下线]` 也算条目。
- 🚫 **增长只发生在 `journal/`**：手册不堆过程与历史，只留规矩与用法。
- 什么时候改这份文件：主线变了 / 多了长期规则 / 水位到线。其余一律进 journal。
